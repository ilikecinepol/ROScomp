Автономная полоса препятствий (Unitree Go2 Pro)

Задача

Робот Unitree Go2 Pro должен полностью автономно пройти замкнутую петлю по физической полосе препятствий: стартовать из точки, обойти все препятствия — каждое по одному разу, в произвольном самостоятельно выбранном порядке — и вернуться в ту же точку (старт = финиш). Порядок обхода выбирает решение команды; организатор его не задаёт и не оценивает.

Всё выполняется на борту (Raspberry Pi 5): без телеопераций, без внешних вычислений и без вмешательства человека после сигнала старта.

Петля либо пройдена (все препятствия закрыты и робот вернулся в точку старта → результат идёт в зачёт), либо не пройдена (засчитанного времени нет). Промежуточных состояний нет: не пройдено хотя бы одно препятствие — незачёт заезда.

Зачёт — по времени. Время каждого заезда нормируется на эталонный прогон организатора на той же раскладке (меньше — лучше); нормировка уравнивает сложность разных раскладок.

Арена и препятствия

Старт и финиш

  • Одна физическая точка — совмещённые старт и финиш, размечена полосами на полу.

  • Стартовая ориентация робота — всегда в одном направлении.

  • Возврат засчитывается, когда центр робота пересекает линию старта (при условии, что все препятствия уже пройдены).

Препятствия

Все элементы рассчитаны под квадропеда. Габариты — ориентировочные; финальные значения публикует оргкомитет.

#

Препятствие

Ориентир по габаритам

1

A‑образная горка (A‑рама) — подъём по одному скату, через конёк, спуск по другому

скаты 1.2–1.5 м, наклон ~25–30°, высота конька ~0.5 м, ширина ~0.6 м, поперечные планки‑грипы

2

Подвесной мост — качающийся настил на цепях

пролёт 1.5–2.0 м, ширина 0.5–0.6 м, настил на высоте 0.15–0.25 м, качание ±5–8°

3

Балансир‑качели — доска на центральной оси; робот перекидывает её через точку баланса

доска ~1.6–2.0 м, ширина 0.5–0.6 м, ось на высоте 0.15–0.20 м, наклон в покое ~10–12°

4

Змейка вокруг конусов — слалом между высокими конусами‑стойками

6 конусов высотой ~1.0 м, шаг 0.8–1.0 м, коридор ±0.4 м

5

Две платформы с горками — рампа вверх → платформа‑1 → ступенька вверх → платформа‑2 → рампа вниз

рампы ~20–25°, платформы ~0.6×0.6 м на высоте ~0.25–0.30 и ~0.35–0.45 м, ступенька +0.10–0.15 м, ширина ~0.5 м

Правила прохождения

  • Обход всех: зачёт петли — только при прохождении всех препятствий; ни одно не опционально; частичный обход — незачёт.

  • Произвольный порядок: маршрут между препятствиями робот планирует сам.

  • Направление: A‑рама, мост и змейка — заход с любой стороны; балансир‑качели — со стороны опущенного конца; двойные платформы — со стороны рампы‑подъёма.

  • Каждое препятствие — один зачёт: засчитывается по первому корректному прохождению; повторный проход времени не экономит.

  • Прохождение препятствий и время фиксирует независимая судейская система трекинга (не одометрия робота — она дрейфует).

Робот и программный интерфейс

Платформа

Всем командам предоставляется единый парк Go2 Pro (одна ревизия железа, одна версия прошивки локомоции, одна калибровка сенсоров). Конкретный борт назначается перед заездом; команда его не выбирает и заранее не знает.

  • Шасси: 4 ноги, 12 DoF, ~15 кг, штатная прошивочная MNN‑политика локомоции. Прямого доступа к моторам нет — только высокоуровневые команды скорости/походки/позы. Низкоуровневый LowCmd и отключение прошивочных защит закрыты.

  • Сенсоры: 4D‑LiDAR Go2 L1 (360°), фронтальная RGB‑камера, IMU, одометрия ног, датчики контакта стоп, состояние батареи.

  • Борт‑компьютер команды: Raspberry Pi 5, 8 ГБ — единственный вычислитель для кода команды. Бюджет вычислений планировать под него.

  • Питание: штатная батарея; замена/зарядка — на стороне организатора между заездами.

Судейский образ Pi5

Организатор поставляет эталонный golden‑image, идентичный на всех Pi5; команда получает копию заранее. Установка своей ОС / перепрошивка Pi5 запрещены.

Предустановлено: Ubuntu 24.04 arm64; ROS 2 Jazzy (rclcpp/rclpy, tf2, ros2 bag); драйвер go2_ros2_sdk + WebRTC‑bridge (запускается судейским systemd‑юнитом — команда только подписывается на готовые топики); Nav2, slam_toolbox, pointcloud_to_laserscan, robot_localization (EKF), image_pipeline, cv_bridge; OpenCV, NumPy, SciPy, ONNX Runtime (CPU), Open3D; Python 3.12 с зафиксированным requirements.

Свои пакеты — только в фазе подготовки и только в свой оверлей.

Чем управляем (актуация)

  • Основной канал — /cmd_vel (geometry_msgs/Twist). Ограничения: |vx| ≤ 1.5 м/с, |vy| ≤ 1.0 м/с, |wz| ≤ 2.0 рад/с — большее обрезается.

  • Sport API (походка/поза/высота корпуса; высота — только в Pose‑режиме FSM) через служебный сервис SDK.

  • Watchdog /cmd_vel: нет свежей команды > 500 мс → мягкий переход в стойку (учитывает джиттер Pi5; это защита, не наказание).

  • Опасные движения (flip/handstand/jump/резкие развороты), низкоуровневый доступ, RF‑пульт, WebRTC в обход драйвера и смена прошивки — заблокированы.

Доступ и запуск

  • Подключение — удалённо по VPN: персональный WireGuard‑профиль даёт доступ только к назначенному Pi5 по SSH‑ключу команды. Доступа к чужим роботам и судейской сети нет.

  • Фаза подготовки: VPN + SSH + интернет на Pi5 доступны — команда собирает решение, ставит зависимости в оверлей, тестирует.

  • Зачётный прогон: за 10 минут до слота код замораживается (фиксируется контрольная сумма решения, каталог — read‑only), интернет отключается, борт остаётся только со служебными топиками. При переносе на резервный борт разворачивается ровно этот зафиксированный артефакт.

  • Сигнал старта даёт судья со своей станции; узлы команды обязаны дождаться сигнала и не подавать команды движения до него.

Ограничения

  1. Нет внешней сети во время прогона — интернет/облако/внешние адреса недостижимы; любой исходящий коннект наружу трактуется как нарушение.

  2. Нет доступа к данным арены — в образе нет карт, координат и планов; захардкоженные под раскладку координаты бессмысленны (раскладка меняется).

  3. Только Pi5 — внешние вычислители, второй компьютер, телеоперация и вмешательство человека после старта запрещены.

  4. Заблокированы опасные движения и низкоуровневый доступ к приводам.

Нарушение пп. 1–3 — незачёт заезда; попытка обойти изоляцию/песочницу — дисквалификация (решение оргкомитета).

⚠️ Важно: каждый участник делает это сам

Доступ к репозиторию выдаётся индивидуально. Каждому члену команды необходимо самостоятельно открыть задачу на платформе и пройти шаги ниже. Если участник этого не сделал — у него не будет доступа к репозиторию (он увидит ошибку 404), даже если репозиторий уже создан кем-то из команды. Недостаточно, чтобы репозиторий создал один человек — авторизоваться через платформу должен каждый.

Шаг 1. Создание репозитория

  1. Нажмите кнопку «Создать репозиторий» в нижней панели задачи.

  2. Дождитесь завершения создания.

Этот шаг достаточно выполнить одному участнику команды — репозиторий создаётся один на команду. Но открыть задачу и пройти авторизацию (Шаг 2) должен каждый.

Шаг 2. Авторизация в репозитории (выполняет каждый участник)

  1. Перейдите по ссылке на репозиторий из нижней панели задачи.

  2. На странице входа GitLab нажмите кнопку «Войти через True Tech Arena»

  3. Вас перенаправит на страницу входа платформы True Tech Arena. Если вы ещё не авторизованы на платформе — потребуется ввести email и пароль от вашего аккаунта на True Tech Arena (те же, что и для входа на платформу). Если вы уже авторизованы — этот шаг должен пройти автоматически.

  4. Вернитесь на вкладку с задачей на платформе. Дождитесь, пока в нижней панели появится ссылка на репозиторий — обычно это занимает 5–10 секунд. Именно возврат на задачу и появление ссылки завершают выдачу доступа — без этого шага доступ может не примениться.

Если видите ошибку 404

При первом открытии GitLab может показать ошибку 404 — это нормально, доступ ещё не успел примениться:

  1. Подождите несколько секунд.

  2. Вернитесь на вкладку с задачей на платформе и обновите её.

  3. Снова откройте ссылку на репозиторий.

Если 404 сохраняется дольше пары минут — убедитесь, что вы выполнили Шаг 2 целиком, включая возврат на вкладку с задачей.

Если ссылка на репозиторий или доступ к репозиторию не появился — обновите страницу задачи ещё раз. Если и после этого ничего не произошло — значит, синхронизация доступа не отработала, и нужно обратиться в поддержку через Чат-бот True Tech Arena (мы добавим участника в группу вручную).

Работа с Git

Push в main отключён намеренно

Прямой push в main запрещён для всех команд True Tech Champ. Ветка под защитой — это исключает риск того, что один неаккуратный force-push сотрёт историю всей команды. Это общая политика, никаких особых ограничений на ваш репозиторий нет.

Стандартный flow через Merge Request

git checkout -b feature/<имя-фичи>
git add . && git commit -m "ваш commit message"
git push -u origin feature/<имя-фичи>

После пуша откройте в GitLab Merge Request в main и смёрджите его сами — права на merge у всех участников команды есть.
