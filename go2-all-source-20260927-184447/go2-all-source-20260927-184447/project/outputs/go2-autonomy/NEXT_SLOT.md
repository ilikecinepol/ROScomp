# Следующий час на полигоне

Эта версия предназначена для проверок. Полное физическое прохождение ею ещё не подтверждено. Сначала устраняем конкретные неизвестные, которые мешают работать на любой из назначенных собак.

| Минуты | Действие | Что должно остаться в записи |
|---|---|---|
| 0–10 | Подключиться по инструкции текущего назначения, получить единственное WebRTC-соединение, запустить observe | Идентификатор устройства, версии, состояние батареи, частоты и форматы потоков, данные для сравнения с предыдущим роботом |
| 10–20 | Неподвижная запись, затем согласованные малые перемещения на свободном полу | Отдельно проверить фактическое движение, знак и масштаб координат, отклик/подтверждение остановки; не считать неподвижность изображения доказательством неисправности IMU |
| 20–30 | Проверить системы координат и метки времени по повторяемому наблюдаемому событию | Что означает robot_pose, где начало/оси, как связаны часы и какая задержка; поворот курса нельзя исправлять постоянной поправкой из прошлого слота |
| 30–45 | Снять конструкции с разрешённых безопасных позиций | Нижняя/верхняя поверхности, две ступени, выступающие стыки, вход/выход, опоры моста/ось качелей, изображение стартовой линии; калибровка камеры отдельно |
| 45–55 | Только при подтверждённой готовности — один ограниченный автономный опыт | Сначала подход и выравнивание на полу; полный заезд не подменяет проверку каждого физического навыка |
| 55–60 | Остановить, проверить состояние, сохранить журналы, освободить клиент по инструкции организатора | report.json, samples.jsonl, NPZ/JPG, версия программы, назначение робота и условия опыта |

Ручные контрольные перемещения выполняются только в разрешённой тренировке под контролем оператора и штатным интерфейсом. Эта таблица не разрешает вмешательство в зачёт после старта.

## Данные, которые нужно уточнить

1. Есть ли уникальный серийный номер в доступном потоке? Сейчас live требует его. Если его нет, нужен предоставленный организатором способ проверяемо связать назначенный Pi с собакой; одинаковые версии прошивки этого не делают.
2. Откуда берётся время каждого потока? В нашей записи камера и облако пока не дают подтверждённой общей шкалы. Константный stamp карты не доказывает ни свежесть, ни заморозку самой карты.
3. Есть ли сырой лидар/доступные лучи, калибровка камеры и привязка robot_pose к корпусу? Воксельная занятость не доказывает отсутствие препятствия в пустой ячейке.
4. Как выглядят разрешённые входы/выходы и точные критерии прохождения? Для распознавания механизма нужны данные, различающие мост и качели.
5. Какой официальный интерфейс старта и как детектируется стартовая линия? В пакете есть только локальный учебный сигнал запуска, а детектор реальной линии пока не реализован.

## До слота

Команда уже может запускать demo/replay, улучшать детекторы на записях, добавлять регрессионные случаи и изучать причины остановок. В профили реальных собак не переносим подтверждения из искусственных тестов. Настройки ширины, погрешности и скорости уточняем измерением, а не ослаблением проверок ради движения.
