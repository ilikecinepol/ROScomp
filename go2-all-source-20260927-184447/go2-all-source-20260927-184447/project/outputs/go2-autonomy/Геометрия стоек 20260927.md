# Разбор геометрии стоек

Автономное прохождение пока не подтверждено. Эта итерация выполнена на скачанных данных, без подключения и команд движения. Последняя установленная на Pi версия остаётся `training-f171f4e33c0afeca479f`.

## Найденная проблема

В кадре `20260927T102612.913780Z/cloud_000015.json` детектор видит четыре полосатые стойки. При этом проекция одного кандидата лидара проходит между двумя визуальными стойками. Прежнее правило принимало соответствие по расстоянию до центра прямоугольника, хотя проекция не попадала внутрь него.

Добавлена консервативная проверка попадания проекции в прямоугольник визуальной стойки. Порог расстояния 35 пикселей и проверка однозначности 5 пикселей сохранены. Это условие применяется в офлайн-аудите и оценке поправок калибровки; в рабочий контур движения оно пока не интегрировано. Старые наборы признаков без прямоугольников теперь требуют пересоздания, чтобы не смешивать разные правила проверки.

Прямоугольник — лишь область визуального кандидата, а не доказательство принадлежности точки реальной стойке. Попадание внутрь само по себе не подтверждает калибровку.

## Результат

- Обработано 109 уникальных кадров без ошибок.
- Отсеяно 20 ранее принятых соответствий на 20 кадрах: их проекции находились вне области соответствующего визуального кандидата.
- Число кадров с тремя принятыми соответствиями осталось 10.
- На выбранном свежем кадре число принятых соответствий уменьшилось с двух до одного.
- Полный набор из 311 тестов прошёл. После дополнительной проверки формата старого кэша отдельно прошли 10 затронутых тестов. Полный набор после этого последнего изменения не повторялся.

## Визуальная проверка

`diagnostic-20260927/projection-review.png`: слева камера, голубые рамки C0–C3 — визуальные кандидаты, цветные линии L — проекции объектов лидара. Справа — облако сверху, положение робота и кандидаты ряда. Два кандидата лидара наблюдены только частично. Один из кандидатов ряда не имеет видимой проекции в текущем изображении; его нельзя считать подтверждённой четвёртой стойкой.

Новый инструмент `work/go2-autonomy/render_projection_review.py` воспроизводит разбор любого сохранённого парного кадра. `audit_camera_projection.py` теперь сохраняет прямоугольники, гипотезы рядов, глубины и число проецируемых точек внутри изображения для каждого кандидата.

Следующий шаг: проверить конкретные соответствия объектов между разными положениями робота, включая неполные и выходящие из поля зрения объекты. Нельзя подгонять калибровку по общему количеству стоек или считать частичный ряд полным. Неподтверждённые временные метки лидара остаются отдельным ограничением.
