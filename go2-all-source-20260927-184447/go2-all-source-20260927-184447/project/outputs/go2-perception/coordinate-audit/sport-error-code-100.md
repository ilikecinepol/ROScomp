# Что означает SportModeState.error_code = 100

Проверено 16 сентября 2026 года. Проверка только документов и локального архива; подключений к роботу и команд движения не было.

## Официальная документация

На странице производителя [Motion Services Interface V2.0](https://support.unitree.com/home/en/developer/Motion_Services_Interface_V2.0), в разделе состояния высокого уровня, `error_code()` описывает текущий режим. Таблица состояний для `rt/sportmodestate` содержит:

| Значение | Название производителя |
|---|---|
| 100 | Agile |
| 1001 | Damping |
| 1002 | Standing Lock |
| 1013 | Balance Standing |
| 1015 | Regular Walking |

Таким образом, **100 в этой версии протокола — идентификатор режима Agile, а не ошибка выполнения команды**. Возвращаемый код вызова Sport API — отдельная сущность; его нельзя смешивать с полем состояния.

Ограничение первоисточника: страница относится к Go2 Edu с ПО не ниже V1.1.6. Применимость всей таблицы к конкретной версии Go2 Pro этой проверкой не установлена. Само значение 100 не подтверждает физическую готовность к движению или отсутствие других неисправностей. Страница прочитана непосредственно в браузере; обычное текстовое извлечение JS-страницы не сработало.

## Подтверждение неоднозначности старого имени поля

В [локальном снимке ОС](C:/Users/VladO/Downloads/unitree-go2-pro-os-main.zip), внутренний путь `unitree-go2-pro-os-main/rootfs/unitree/module/programming_actuator/state_update_thread.py`:

- строки 17–19 описывают отдельные биты `error_code` как флаги непрерывной походки, энергосбережения и следования;
- строка 44 реально проверяет `sport_mode_state.error_code & 1`, затем устанавливает признак непрерывной походки;
- строки 12–14 определяют `mode=0` как покой/обычную стойку. Это также подтверждает [официальный README unitree_ros2](https://github.com/unitreerobotics/unitree_ros2#state-acquisition).

Это не полная расшифровка числа 100 для старой версии, но прямое свидетельство, что правило «любой ненулевой SportModeState.error_code означает аварию» неверно для данного снимка.

## Вывод для короткого теста

Нет оснований объявлять наблюдённое значение 100 блокирующей аварией только по названию поля. После штатного переключения режима значение может измениться: сравнивать его с исходным состоянием корректно после завершения переключения. Подтверждение StopMove, свежие данные, устойчивое положение и наблюдение оператора остаются самостоятельными условиями; код 100 их не заменяет.
