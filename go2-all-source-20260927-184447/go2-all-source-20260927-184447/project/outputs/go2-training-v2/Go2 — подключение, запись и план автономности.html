01. Что готово и как это устроено

Робот сейчас отключён. Версия 2 подготовлена и проверена локально. Она ещё не установлена и не испытана на физическом роботе. Перед следующим слотом загрузите серверные файлы по шагу 5.
Ваш ПК
клавиатура + окно⇄ VPN / SSH ⇄Pi организаторов
управление + запись⇄ WebRTC ⇄Go2
датчики + штатная ходьба

Собственный Raspberry Pi для удалённого полигона не нужен: используем назначенную плату организаторов. Адрес 192.168.11.81 — адрес текущего Pi-0008 для SSH, а не веб-страница и не обязательно адрес самой собаки. При новом назначении уточните адрес и ключ.

Ручная тренировка

ПК отправляет нажатия. Pi проверяет связь и датчики, затем передаёт команду скорости. Камера идёт обратно в окно. Закрытие окна завершает ручной сеанс.

Будущий автономный заезд

Распознавание, выбор пути и управление работают на Pi. ПК не ведёт робота и не считает маршрут. После старта вмешательство команды в зачётный заезд запрещено.

Что изменилось: Пробел и кнопка разрешения больше не нужны. При свежих данных и активном окне подготовка идёт автоматически. Само подключение движения не вызывает. Есть четыре профиля и отдельные кнопки записи.

Старый код симулятора L1 не является готовым решением реального полуфинала. Текущий автономный пакет экспериментальный: полный физический проход не подтверждён.

02. Подготовить другой ПК — один раз

  1. Распакуйте Go2-training-v2.zip полностью в C:\Go2. Внутри должны быть START.cmd, папки work и server. Не запускайте из ZIP.
  2. Установите Python 3.12 с Python Launcher и Tcl/Tk, OpenVPN Connect и компонент Windows «Клиент OpenSSH», если их нет.
  3. Получите выданные команде robot_8.ovpn и SSH-ключ pi-0008.txt. В комплекте их нет. Не отправляйте ключи в репозиторий.
  4. В OpenVPN Connect: Import Profile → File → выбрать профиль → Connect → дождаться Connected.
  5. На первом ПК завершите управление и отключите тот же VPN-профиль перед использованием на другом ПК.

Все следующие команды с синей подписью выполняются на вашем Windows-ПК в PowerShell, не внутри SSH. Вставляйте блок целиком. Если шаг завершился ошибкой, исправьте её перед следующим шагом.

py -3.12 --version
PowerShell · ваш Windows-ПК — Создать окружение клиента
cd C:\Go2
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install Pillow

Интернет требуется для установки Pillow. Для нашего окна не нужно ставить ROS или OpenCV на Windows.

PowerShell · ваш Windows-ПК — Проверить окно БЕЗ робота
.\.venv\Scripts\python.exe .\work\go2-teleop\keyboard_client.py --dry-run

Демонстрация не соединяется с Pi и не записывает датчики. Закройте её перед настоящим подключением.

03. Разместить ключ и проверить доступ

Если файл ключа лежит в «Загрузках», выполните блок ниже. Если у вас уже настроен этот ключ, повторно копировать его не нужно. При другом расположении измените путь исходного файла.

PowerShell · ваш Windows-ПК — Положить ключ в личную папку SSH
$keyDir = Join-Path $env:USERPROFILE '.ssh\go2-pi-0008'
New-Item -ItemType Directory -Force -Path $keyDir | Out-Null
$keyFile = Join-Path $keyDir 'id_ed25519'
Copy-Item -LiteralPath "$env:USERPROFILE\Downloads\pi-0008.txt" -Destination $keyFile
$account = [System.Security.Principal.WindowsIdentity]::GetCurrent().Name
icacls $keyFile /inheritance:r
icacls $keyFile /grant:r "${account}:(R)"
PowerShell · ваш Windows-ПК — Проверить доступность SSH
Test-NetConnection 192.168.11.81 -Port 22

Ожидается TcpTestSucceeded : True. Неудачный ping сам по себе ещё не доказывает отсутствие SSH.

PowerShell · ваш Windows-ПК — Первый вход по SSH
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\go2-pi-0008\id_ed25519" ubuntu@192.168.11.81

При первом входе сверить отпечаток сервера с организаторами или доверенным ПК и лишь после совпадения принять его. При сообщении об изменившемся ключе уточнить смену устройства; не отключать проверку.

SSH · удалённый Pi — Проверить назначенную плату и выйти
hostname
exit

Ожидаемое имя — pi-0008. После exit вы снова в PowerShell Windows. Вход по SSH сам по себе окно камеры не открывает.

04. Проверить основу на Pi без движения

Эта проверка не открывает соединение с роботом и не отправляет команд движения. Предполагается выданная организаторами среда ~/ai-robot.

PowerShell · ваш Windows-ПК — Проверить Python, helper и место на диске
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\go2-pi-0008\id_ed25519" ubuntu@192.168.11.81 "hostname; test -f /home/ubuntu/ai-robot/go2.py; /home/ubuntu/ai-robot/venv/bin/python --version; df -h /home/ubuntu/ai-robot"

Если go2.py или venv/bin/python отсутствуют, это другой образ или не тот пользователь. Сначала сверить инструкцию текущего слота. Не переносить на плату образ ОС самой собаки и не переустанавливать системный Python.

Наш клиент рассчитан на уже настроенный WebRTC helper организаторов. Параллельно запускать 01_read_state.py, ROS-мост, другой клиент или автономный контроллер нельзя: робот принимает один WebRTC-сеанс.

Ниже команды из C:\Go2. Они загружают программу, но не запускают управление. На Pi работаем в своей папке team_wolf_setup.

06. Подключиться и управлять

Запускайте в тренировочный слот, когда оператор полигона готов и путь свободен. Весь текущий сеанс ограничен 300 секундами, включая подготовку связи; начало новой записи таймер сеанса не обнуляет. Для следующих пяти минут завершите сеанс и подключитесь снова.

PowerShell · ваш Windows-ПК — Открыть настоящее управление
cd C:\Go2
.\.venv\Scripts\python.exe .\work\go2-teleop\keyboard_client.py --host 192.168.11.81

Или дважды нажмите START.cmd. Окно появляется на Windows. Клиент сам запускает сервер на Pi, временно освобождает подключение от fleet-dog и восстанавливает службу при завершении, если она была активна. Подготовка может занимать десятки секунд.

  1. Сделайте окно активным, отпустите все клавиши и дождитесь надписи «Готово».
  2. По умолчанию выбран профиль «Точный». Удерживайте направление; отпускание останавливает движение.
  3. При смене профиля робот останавливается. Дождитесь совпадения выбранного профиля с надписью «Профиль Pi».
  4. После потери фокуса или связи отпустите клавиши и нажмите направление заново после готовности. Старое удержание не должно продолжить движение.

Пробел не требуется и не включает движение. В поле подписи и списке профилей клавиши не управляют собакой. После выбора профиля фокус возвращается в окно. Если клавиша была нажата при подготовке, отпустите её и нажмите снова.

Важно: это ручной пульт, он не распознаёт край платформы и не объезжает препятствия автоматически. Ограничение скорости и проверка свежести датчиков не гарантируют, что лапа не соскользнёт.

07. Какие скорости выбирать

Это начальные настройки для испытаний, а не подтверждённые скорости прохождения. Поле скорости — желаемая команда; фактическое перемещение зависит от походки, наклона и сцепления. По текущему API организаторов пределы — 0,6 м/с вперёд, 0,5 м/с боком, 1 рад/с поворот. Старые общие цифры из раннего описания полуфинала для этого пульта не используем.

ПрофильВперёд / назадВбокПоворотКогда начать с него
Точный0,10 м/с0,08 м/с0,20 рад/сПервое знакомство, выравнивание на полу перед рампой
Препятствие0,15 м/с0,10 м/с0,25 рад/сПробный прямой проход после проверки точного подхода
Пол0,30 м/с0,15 м/с0,50 рад/сСвободные участки между препятствиями
Быстрый0,60 м/с0,50 м/с1,00 рад/сТолько проверенная свободная площадка; не первый тест рампы

При движении по диагонали модуль поступательной команды ограничен скоростью «вперёд» выбранного профиля. Эти значения задаются на Pi: подмена числовой скорости в окне не позволяет превысить пределы.

Если нет продвижения, не продолжайте давить W и не увеличивайте скорость вслепую. Отпустите клавишу, оцените положение с оператором, сохраните попытку. Застревание может быть связано с выравниванием, кромкой, сцеплением или режимом ходьбы.

Как пробовать препятствие

  1. Выравнивайте корпус по центру входа на ровном полу. Нужен запас до рампы, чтобы не разворачиваться уже на узком настиле.
  2. Запишите несколько секунд неподвижного состояния. Начните короткий подход с 0,10 м/с, проверьте реакцию на отпускание.
  3. Для первого прохода испытывайте 0,10–0,15 м/с. Держите направление ровным, не чередуйте большие повороты и боковые команды.
  4. На кромках и качелях наблюдайте крен, тангаж и фактическое продвижение. Не считайте остановку на самой точке баланса универсально безопасной стратегией.
  5. После съезда дождитесь устойчивого положения на полу, затем заканчивайте запись.
  6. Увеличивайте скорость только после повторяемых проходов. Сначала сокращайте лишние развороты и время прицеливания, затем ускоряйте проверенные участки.

Точные параметры походки для подъёма и ступеней нужно проверить по доступному Sport API. Мы не управляем отдельными лапами: «поднять лапу выше» нельзя обещать обычной командой Move.

08. Записать только нужную попытку

  1. Поставьте робота перед нужным участком. Остановитесь на полу.
  2. Нажмите «● Начало записи». Это останавливает движение на границе записи. Дождитесь надписи «● ПИШЕМ: run_001».
  3. Оставьте 3–5 секунд неподвижного состояния, затем выполняйте попытку. Для неудачной попытки данные так же полезны.
  4. При необходимости остановитесь и добавьте подпись: «первый контакт с рампой», «не продвигается», «съезд завершён». Ввод подписи останавливает движение.
  5. После прохода остановитесь на полу, запишите ещё 3–5 секунд. Нажмите «■ Конец записи».
  6. Дождитесь «сохранено: run_001». Надпись появляется после обработки очереди и закрытия файлов. Можно начать следующую запись в том же сеансе — будет run_002.
  7. Нажмите «Завершить и сохранить» перед выходом. Дождитесь закрытия или сообщения о восстановлении службы. Скачайте данные до окончания доступа.

Без нажатия «Начало записи» камера и контроль состояния работают, но фотографии, карты и полная телеметрия прогона не сохраняются. Небольшой диагностический журнал событий ведётся весь сеанс. Если закрыть окно с активной записью, сервер пытается штатно завершить её; при обрыве питания полноту нужно проверять.

Pi: /home/ubuntu/ai-robot/team_wolf_setup/teleop_logs/
  ИМЯ_СЕАНСА_UTC/
    run_001/                 ← одна выбранная попытка
      events.jsonl           ← нажатия, Move/Stop, ответы, отметки
      telemetry.jsonl        ← состояние, IMU, одометрия
      camera.jsonl + camera/ ← кадры и времена приёма
      maps.jsonl + maps/     ← доступные сжатые воксельные карты
      recording.json         ← complete=true после закрытия записи
    events.jsonl             ← диагностика всего сеанса
    summary.json             ← итог после завершения сеанса
    run_status.json          ← завершение и восстановление службы
    library.log              ← сообщения WebRTC-библиотеки

Записывается доступная обработанная воксельная карта, не подтверждённый сырой лидар. Камера сохраняется отдельными JPEG до 5 Гц, предпросмотр — около 2 Гц. Время приёма на Pi не равно аппаратному времени съёмки. Имена сеансов в UTC, поэтому могут отличаться от московского времени на три часа.

09. Скачать и проверить результат

Для первого раза проще скачать каталог сеансов целиком. Это может быть долго, если в нём накопились старые прогоны. Команды выполняются на ПК после завершения управления.

PowerShell · ваш Windows-ПК — Скачать все сеансы
cd C:\Go2
New-Item -ItemType Directory -Force .\recordings | Out-Null
scp -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\go2-pi-0008\id_ed25519" -r ubuntu@192.168.11.81:/home/ubuntu/ai-robot/team_wolf_setup/teleop_logs .\recordings

Чтобы скачать только один сеанс, скопируйте его имя из окна или получите список:

PowerShell · ваш Windows-ПК — Показать сеансы на Pi
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\go2-pi-0008\id_ed25519" ubuntu@192.168.11.81 "ls -1 /home/ubuntu/ai-robot/team_wolf_setup/teleop_logs"
PowerShell · ваш Windows-ПК — Скачать один выбранный сеанс
$sessionName = Read-Host "Вставьте имя сеанса из списка, без пути"
if ($sessionName -notmatch '^\d{8}T\d{6}(\.\d+)?Z$') { throw "Неверное имя сеанса" }
New-Item -ItemType Directory -Force .\recordings | Out-Null
scp -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\go2-pi-0008\id_ed25519" -r "ubuntu@192.168.11.81:/home/ubuntu/ai-robot/team_wolf_setup/teleop_logs/$sessionName" .\recordings

Внутри скачанного сеанса проверьте run_001/recording.json: complete: true; наличие непустой телеметрии и кадров. В summary.json смотрите writer_error, errors и final_stop_acknowledged; в run_status.json — восстановление службы. «Скопировано» не означает «препятствие пройдено».

Для анализа передавайте всю папку выбранного сеанса. Полезно приложить описание: препятствие, направление, выбранная скорость, что получилось и на какой секунде возникла проблема. Данные останавливавшегося или застрявшего робота особенно важны.

10. Скорость данных и телеметрия

Нужно различать три величины: частоту сообщений (Гц), объём потока (Мбит/с) и задержку от события до отображения (мс). У нас пока нет достоверного измерения полной задержки робот → Pi → Windows и пропускной способности VPN.

ПотокЧто известноЧто это означает
Состояние / IMU в SportОколо 20 Гц в сохранённом ручном сеансеНовое сообщение примерно раз в 50 мс на Pi
ОдометрияОколо 19 ГцПримерно раз в 53 мс; координаты дрейфуют
Воксельная картаОколо 7 Гц при приёмеНе 7 сырых сканов в секунду; карта может иметь свою обработку
Камера на PiВ предыдущей записи около 14 кадров/сСохраняем JPEG до 5 Гц
Предпросмотр на WindowsОколо 2 кадров/с, задано программойОколо 500 мс между показанными кадрами, плюс неизвестная задержка
Статус / команды пультаДо 10 ГцЭто не гарантия задержки 100 мс

Пример: при 0,6 м/с за 0,5 секунды робот может переместиться примерно на 30 см, а при 0,1 м/с — на 5 см. Это иллюстрация расстояния между обновлениями картинки, не измерение тормозного пути. Для узкой рампы управление «по запоздалому изображению» заметно сложнее.

Поможет ли телеметрия в реальном времени?

Да. В новой версии показаны возраст состояния, скорость по датчикам, наклон и подтверждённый Pi профиль. Они помогут отличить «команда отправлена» от «робот действительно движется». Рисунок маршрута по одометрии можно добавить для разбора, но нельзя принимать его за точную карту пола.

Предпочтительная схема: полные данные сохранять на Pi, на ПК передавать лёгкий статус и предпросмотр, после попытки скачивать запись. Одновременная непрерывная выгрузка всех карт и кадров может конкурировать с управлением за сеть. При неизвестной задержке не увеличиваем качество видео вслепую.

На следующем слоте измерим отдельно: RTT команд и подтверждений на одних часах; интервалы и размер кадров; задержки очередей; p50/p95 и максимум; загрузку CPU, диска и сети. Для абсолютной задержки камеры нужны синхронизированные часы или специально наблюдаемое событие. Ранее времена PTS и карт в записи вели себя несогласованно — просто вычитать их из часов ПК нельзя.

11. Три препятствия: рабочая гипотеза

По фотографиям для плана предполагаем: А-образная горка, балансир-качели и платформы с двумя ступенями. Точный текущий набор трёх препятствий ещё нужно подтвердить. Первоначальные условия перечисляли пять; тренировочный набор не означает автоматического изменения правил зачёта.
ЭлементЧто робот должен определитьЧто проверять на испытании
А-образная горкаВход, центральную ось, оба края, подъём → гребень → спускВыравнивание до въезда; изменение тангажа; полное возвращение на пол
Балансир-качелиОпущенный вход, ось доски, начало перевеса, положение выходаИзменение наклона самой доски; сохранение опоры; завершение съезда. Не путать с подвесным мостом
ПлатформыРампу, нижнюю площадку, промежуточную ступень, верхнюю площадку, спускДва подъёма, реальные щели и выступы стыков, достаточную опорную ширину

В фотографиях пользователь отметил две ступени и выступы на переходах рамп. Это нужно измерить на месте: по перспективному фото нельзя надёжно получить сантиметры. Сходство цвета матов и настила делает цвет недостаточным признаком проходимости.

Отсутствие точек лидара у края не доказывает наличие свободного пола. Для прохода нужно подтверждать опорную поверхность. Движущуюся доску нельзя считать неизменной частью статической карты.

12. План: от записи к автономному проходу

Не обязательно сначала идеально пройти всю цепочку вручную. Нам полезнее короткие, подписанные попытки каждого элемента. Из них получим параметры движения и ошибки восприятия. Воспроизведение «W три секунды, A одну секунду» не будет устойчивой автономностью.

Этап 1 · подготовить следующий слот

Проверить демо новой версии на ПК, подготовить ключи, уточнить три препятствия, направления, критерии зачёта, размеры и правила повторной попытки. Получить актуальный сигнал старта и список разрешённых режимов. Результат: одна проверенная версия клиента и сервера, согласованная программа испытаний.

Этап 2 · измерить движение на ровном полу

Записать покой, короткое движение 0,10 м/с, остановку, затем 0,15 и 0,30 м/с на свободном участке. Сопоставить команды, ответы, одометрию и измерение оператором на полу. Проверить направления осей, реальные остановки и задержки. Не считать краткий тест уже доказанной калибровкой.

Этап 3 · собрать данные о каждом входе

Записать 2–3 подхода с разных небольших смещений и неподвижный обзор. Попросить измерить ширину, высоты ступеней, выступы и щели. Если есть собственный Go2 Air, стенд с похожим настилом полезен для камеры и выравнивания; перенос устойчивости походки на Pro всё равно проверяем отдельно.

Этап 4 · научить программу видеть геометрию

Объединить камеру и доступные 3D-данные: камера помогает распознать тип, 3D — оценить положение и поверхность, IMU — учесть наклон корпуса. Проверить калибровку камеры, преобразования между датчиками, систему координат карты и временные метки. На сохранённых данных сравнивать найденную ось и края с ручной разметкой.

Этап 5 · автономно подойти и остановиться перед входом

Сначала программа только строит предложения команд по записи. Затем под наблюдением оператора испытываем короткий подход на полу: найти вход → выровняться → остановиться до рампы. Критерий перехода: повторяемый подход с разных стартовых смещений без ухода за границы.

Этап 6 · отдельный навык на каждый элемент

Для каждого сделать состояния: подход → выравнивание → въезд → проход → съезд → подтверждение завершения. Использовать наблюдения и прогресс, а не только таймер. При потере опоры, непонятной геометрии, устаревших данных или отсутствии продвижения — определённая остановка/восстановление, испытанное отдельно. Не маскировать проблему повышением скорости.

Этап 7 · собрать полный маршрут

Хранить список обнаруженных объектов и статус прохождения; не считать один объект дважды. Планировать вход и выход каждого элемента, учитывать разрешённое направление. Для трёх известных объектов всего шесть порядков: сравнивать время пути, подходов и риск. Если обзор неполный — дообследовать доступную часть арены.

Этап 8 · вернуться к старту

Запомнить старт в согласованной системе координат, распознавать его линию/окружение при возвращении. Одометрия сама по себе недостаточна. Завершение препятствия по внутренним датчикам — наша оценка, зачёт подтверждает независимый судья.

Этап 9 · добиться повторяемости и ускорять

Предлагаемый внутренний ориентир: 5 последовательных удачных проходов каждого элемента, затем несколько полных петель при изменённых начальных положениях. Это не гарантия безотказности. Замерять время по участкам, число коррекций, остановок и срывов. Ускорять самый дорогой надёжный участок по одному параметру за раз.

Этап 10 · подготовить зачётный запуск

Работа только на Pi, официальный старт, зафиксированные зависимости и версия, отсутствие внешних обращений. Прогон запускается без клавиатурного клиента. Код должен уметь стартовать после чистого перезапуска и сохранять диагностику в разрешённом месте.

Как использовать ближайший слот

Порядок важнее количества минут: проверить интерфейс и остановку → записать ровный пол → один вход → один проход выбранного препятствия → скачать и проверить файлы. При коротком слоте лучше получить одну качественную попытку, чем три неразмеченных прогона без сохранённых данных. Повторять сеансы по пять минут только в пределах выделенного организаторами времени.

Где будет работать автономная программа

На удалённом Pi. Уже существует экспериментальная точка входа /home/ubuntu/ai-robot/team_wolf_setup/autonomy-20260918/autonomous.py, рядом пакет wolf_go2/. Передавать нужно весь пакет. Он ещё не готов к подтверждённому физическому автопроходу; вручную отмечать непроверенные калибровки как готовые нельзя. Новое ручное управление находится отдельно в team_wolf_setup/teleop/.
